# Контекст проекта

Файл читается автоматически в начале каждого диалога. Здесь только то,
чего нет в коде, коммитах и документации, — иначе оно дублируется
и устаревает.

## Что это

Веб-приложение для ООО «СК Русвьетпетро» (нефтедобыча, НАО). Начальник
ЦИТУ каждое утро собирает вручную суточный рапорт в Excel — лист
на семьсот строк с тысячей объединённых ячеек — и в 9:00 докладывает
по нему главному инженеру. Приложение принимает этот файл, хранит
данные, считает сводки за период и собирает презентацию для доклада.

Заменяет настольную программу из соседнего репозитория
`D:\Intellect neftesesrvice\rvp-daily-report`. Тот проект трогать
не нужно: он остаётся в работе, пока веб не заменит его полностью.
Движок разбора (`rvp_report/`) перенесён сюда копией и дальше живёт
здесь своей жизнью.

Полный проект системы — [docs/web-architecture.md](docs/web-architecture.md).
Устройство редактора разметки — [docs/layout-editor.md](docs/layout-editor.md).

## Правила работы над проектом

Соблюдать без напоминаний:

1. **Не выдумывать цифры.** Любое число на странице или слайде должно
   проверяться по рапорту. Расчётные величины помечаются «расч.»
   и раскрываются формулой, происхождение пишется в `ProvenanceEntry`.
   Это требование заказчика, сформулированное прямо.
2. **Не молчать о неполноте.** Пропущенные сутки, неподтверждённые
   показатели, расхождения между источниками — показываются, а не
   сглаживаются. Сумма за месяц из 27 суток не выдаётся за месячную.
3. **Никаких костылей.** Есть стандартный инструмент — берётся он.
   Своя реализация вместо библиотеки, ручной разбор дат вместо
   `timedelta` и подобное — не проходит.
4. **Персональные данные в базу не попадают.** Ни текст обращений
   в здравпункт, ни описание происшествия: и там, и там встречаются
   фамилии с медицинскими подробностями. Закреплено тестами
   в `tests/test_decks.py` и `tests/test_models.py`.
5. **Пороги подбираются на настоящих данных**, а не назначаются.
   Правило, срабатывающее каждый день, хуже отсутствующего.
6. **Русский язык** в интерфейсе, сообщениях, докстрингах
   и сообщениях коммитов. Числа в русской записи: разряды пробелом,
   дробная часть запятой, отсутствие значения — прочерк, а не ноль.

## Как запускать

```bash
docker compose -f deploy/compose.dev.yaml up -d   # база, порт 5442
python manage.py migrate
python manage.py runserver
python manage.py load_reports data_august --user admin
python manage.py crosscheck                        # сверка с соседними сутками
```

Проверки перед коммитом:

```bash
python -m pycodestyle apps config tests rvp_report manage.py
python -m pytest tests -q --ignore=tests/test_parsing.py   # быстрые
python -m pytest tests/test_parsing.py -q                  # на 31 рапорте
```

`tests/test_parsing.py` идёт около пяти минут: гоняет разбор
по всем файлам августа.

## Что надо знать про данные

Найдено при разборе августа, в коде не выводится:

- **Утилизация газа — не измеряемая величина.** За 36 суток она равна
  95,5135 % до пятого знака: факел считается от добычи по нормативу.
  В сводках показываются добыча и факел в тоннах, процент — нет.
  Вопрос задан ЦИТУ, ответа пока нет.
- **Номера скважин не уникальны по компании** — только в пределах
  месторождения.
- **Групповые записи**: вместо номера скважины бывает «76 скважин»
  или «куст №1». Это события по нескольким скважинам сразу, хранятся
  в `GroupEvent`, по скважинам не разносятся.
- **Сокращения месторождений** в блоке бурения: «СХ», «ЗХ», «С.Ошк».
  Связываются синонимами через `manage.py link_aliases`.
- **21.08.2026** — массовый перезапуск 76 скважин после техограничения.
  Реальное событие, ловится только межсуточными проверками.

Подробности — в сообщениях коммитов и в `docs/web-architecture.md`,
раздел «Открытые вопросы».

## Чего делать не нужно

- Трогать настольный проект в соседнем каталоге.
- Класть в репозиторий файлы рапортов, презентации и `.env`.
- Заводить учётные записи с паролями в коде или в фикстурах.
- Менять состав одиннадцати слайдов доклада: он согласован
  с начальником ЦИТУ.
