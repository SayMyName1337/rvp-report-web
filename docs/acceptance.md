# Приёмка

Что проверить перед тем, как признать систему готовой к работе.
Проверки идут в том порядке, в каком система используется: сначала
загрузка, потом доклад, потом сводки.

Каждый пункт — это действие и ожидаемый результат. Если результат
не совпал, система не принята: пункт не «почти работает», а не работает.

## Кто участвует

| Роль в приёмке | Кто |
|---|---|
| Загружает рапорт | начальник ЦИТУ |
| Смотрит доклад | главный инженер |
| Проверяет доступы | администратор системы |

## 1. Доступ

- [ ] Страница открывается по `https://<имя узла>` и не открывается по `http` — происходит переход на защищённый протокол.
- [ ] Без входа ни одна страница не показывается: любой адрес перебрасывает на форму входа.
- [ ] Работник промысла входит и видит разделы «Дашборд», «Сводки», «Суточные рапорты», «Скважины», «Качество данных», «Разметка».
- [ ] Руководство входит и **не видит** раздел «Разметка».
- [ ] Руководство не может скачать исходный файл рапорта — страница отвечает отказом.
- [ ] Выданный при заведении пароль система требует сменить при первом входе.

## 2. Загрузка рапорта

- [ ] Настоящий рапорт за сутки загружается и разбирается.
- [ ] В протоколе разбора указаны отчётная дата, число прочитанных скважин и месторождений.
- [ ] Повторная загрузка того же дня **заменяет** данные, а не удваивает их: число суток в списке не растёт.
- [ ] Загрузка постороннего файла `.xlsx` отклоняется с понятным сообщением, а не падает с ошибкой.

## 3. Сверка с рапортом

Главное требование заказчика: **ни одной цифры, которую нельзя
проверить**.

- [ ] На карточке суток выбрать пять любых чисел и найти их в рапорте. Все пять совпали.
- [ ] Нажать «Откуда цифры»: для каждого показателя указан адрес ячейки, диапазон суммирования или формула.
- [ ] Потери добычи помечены «расч.» и раскрыты слагаемыми.
- [ ] Сумма слагаемых равна показанному итогу.

## 4. Презентация

- [ ] Кнопка «Скачать презентацию» отдаёт файл `.pptx`.
- [ ] В презентации одиннадцать слайдов в согласованном порядке.
- [ ] Цифры на слайдах совпадают с карточкой суток.
- [ ] Презентация открывается в PowerPoint без предупреждений.
- [ ] Диаграмма на слайде «Потенциал» правится средствами PowerPoint, то есть является диаграммой, а не картинкой.
- [ ] Если образ собран с `WITH_PDF=1`, кнопка «PDF» отдаёт PDF. Если нет — сообщает, что перевод недоступен, и не отдаёт битый файл.

## 5. Полнота данных

- [ ] В списке суток пропущенные дни показаны отдельной строкой с числом суток.
- [ ] На странице сводки за месяц с пропусками написано «Данные неполные» и перечислены недостающие даты.
- [ ] Сводка за квартал, в котором есть только один месяц, полной не считается.

## 6. Сводки за период

- [ ] Переключение недели, месяца, квартала, полугодия и года меняет цифры.
- [ ] Произвольный период задаётся двумя датами.
- [ ] Сумма добычи за полный месяц совпадает с нарастающим итогом рапорта за последние сутки месяца — расхождение в пределах округления.
- [ ] На графике суточной добычи пропущенные сутки показаны разрывом, а не соединены линией.

## 7. Сверка с соседними сутками

- [ ] Раздел «Качество данных» показывает межсуточные замечания.
- [ ] Замечания читаемы: их единицы за месяц, а не десятки.
- [ ] Нажатие «Разобрано» убирает замечание из требующих внимания, но не удаляет его.
- [ ] Руководство кнопку «Разобрано» не видит.

## 8. История скважины

- [ ] Раздел «Скважины» показывает перечень по накопленным потерям.
- [ ] Отбор по месторождению и номеру работает.
- [ ] На карточке скважины подряд идущие сутки простоя свёрнуты в один отрезок.
- [ ] Если есть остановки вскоре после ремонта, рядом с ними стоит оговорка о том, что связь с ремонтом отсюда не следует.

## 9. Изменение шаблона рапорта

Проверка того, ради чего строился редактор разметки.

- [ ] Взять копию рапорта, переименовать в ней подпись строки, загрузить.
- [ ] Сутки помечены «Требуют подтверждения», а показатель попал в раздел «Разметка».
- [ ] На странице подтверждения показан кусок листа с подсветкой и предложена догадка.
- [ ] После указания ячейки и повторной загрузки пометка снимается, значение верное.
- [ ] Загрузка **неизменённого** рапорта после этого даёт тот же результат, что и раньше: поправка ничего не сломала.

## 10. Персональные данные

- [ ] В базе нет текста обращений в здравпункт — только количество.
- [ ] В базе нет описания происшествия — только ДЗО, месторождение, область события и тип.
- [ ] Автоматические проверки, закрепляющие это, проходят:

```bash
docker compose -f deploy/compose.yaml --env-file .env \
    run --rm web manage test 2>/dev/null || \
    docker compose -f deploy/compose.yaml --env-file .env \
    run --rm web python -m pytest tests/test_decks.py tests/test_models.py -q
```

## 11. Журналы

- [ ] Журнал выдач показывает, кто и когда скачал презентацию или исходный файл.
- [ ] Журнал поправок к разметке показывает автора, время и повод.
- [ ] Ни один из журналов не чистится из интерфейса.

## 12. Эксплуатация

- [ ] Перезапуск узла поднимает все службы без ручного вмешательства.
- [ ] Резервная копия создаётся по расписанию.
- [ ] **Восстановление из копии проверено на отдельном узле**, данные на месте.
- [ ] Администратор знает, где смотреть журналы каждой службы.

## Известные ограничения

Не ошибки, а осознанные решения. Проверяющий должен о них знать.

1. **Разметка держится на текстах заголовков.** Переименование
   заголовка переживается, только если синоним внесён через редактор
   разметки или в схему. Иначе берётся эталонный адрес и выдаётся
   предупреждение — молча неверных цифр не будет.
2. **Утилизация газа не измеряется.** В рапорте она постоянна: факел
   считается от добычи по нормативу. Поэтому в сводках показываются
   добыча и факел в тоннах, а не процент. Вопрос к ЦИТУ открыт.
3. **Групповые записи не разносятся по скважинам.** Строки вида
   «76 скважин» хранятся отдельно: в рапорте не сказано, о каких
   именно скважинах речь.
4. **«Остановки вскоре после ремонта» — наблюдение, а не вывод.**
   Среди них попадаются плановые: вывод на КВД, ограничения добычи.
5. **Исходные файлы рапортов хранятся целиком** — они нужны для
   повторного разбора и для сборки презентации. Значит, персональные
   данные есть в файловом хранилище, хотя их нет в базе. Решение
   о хранении принято владельцем данных.
