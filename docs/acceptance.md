# Программа и методика приёмочных испытаний

Информационная система «Суточный рапорт». ООО «СК Русвьетпетро».
Редакция от 17.09.2026.

Документ определяет состав и порядок проверок, выполняемых перед
вводом системы в промышленную эксплуатацию.

Каждая проверка содержит выполняемое действие и ожидаемый результат.
Проверка считается пройденной при полном совпадении фактического
результата с ожидаемым. Частичное совпадение результатом
не является.

## Участники испытаний

| Проверяемая область | Исполнитель |
|---|---|
| Загрузка суточного рапорта | начальник ЦИТУ |
| Материалы доклада | главный инженер |
| Разграничение доступа, эксплуатация | администратор системы |

## 1. Доступ к системе

- [ ] Система открывается по адресу `https://<имя узла>`. Обращение по протоколу `http` приводит к переходу на защищённый протокол.
- [ ] Без выполнения входа ни одна страница не отображается: обращение по любому адресу перенаправляет на форму входа.
- [ ] Пользователь с ролью «Работник промысла» после входа имеет доступ к разделам «Дашборд», «Сводки», «Суточные рапорты», «Скважины», «Загрузить», «Качество данных», «Разметка», «Инструкция».
- [ ] Пользователь с ролью «Руководство» не имеет доступа к разделам «Загрузить» и «Разметка».
- [ ] Пользователю с ролью «Руководство» отказано в выгрузке исходного файла рапорта.
- [ ] При первом входе система требует замены выданного пароля.
- [ ] Страницы системы открываются и отображаются без искажений в браузерах, применяемых на предприятии: Яндекс Браузер, Google Chrome, Mozilla Firefox.
- [ ] Дашборд читается на экране мобильного устройства: таблицы прокручиваются, страница по горизонтали не смещается.

### 1.1. Ограничение количества попыток входа

- [ ] После пяти подряд неверно введённых паролей вместо формы входа выводится страница «Вход временно закрыт» с указанием срока.
- [ ] Во время действия блокировки вход не выполняется и при вводе верного пароля.
- [ ] Верный пароль, введённый до исчерпания попыток, пропускает в систему; последующие неудачные попытки отсчитываются заново.
- [ ] Блокировка одной учётной записи не препятствует входу другого работника с того же рабочего места.
- [ ] По истечении пятнадцати минут вход выполняется без вмешательства администратора.
- [ ] Команда `manage.py axes_reset_username <имя>` снимает блокировку немедленно.
- [ ] Раздел «Управление», блок Axes, содержит записи о неудачных попытках с указанием учётной записи, сетевого адреса и времени.
- [ ] Сетевой адрес в записях соответствует адресу рабочего места, а не адресу прокси-сервера.

## 2. Загрузка суточного рапорта

- [ ] Файл действующего суточного рапорта принимается и обрабатывается.
- [ ] Протокол разбора содержит отчётную дату, количество обработанных скважин и месторождений.
- [ ] Повторная загрузка за те же отчётные сутки замещает ранее принятые данные. Количество отчётных суток в перечне не увеличивается.
- [ ] Файл формата `.xlsx`, не являющийся суточным рапортом, отклоняется с выводом сообщения; аварийного завершения не происходит.
- [ ] Файл формата `.xls` отклоняется с указанием на необходимость пересохранения.
- [ ] Отклонённый файл в состав данных не включается: показатели за отчётные сутки остаются прежними.

## 3. Проверяемость показателей

Требование заказчика: каждый показатель, отображаемый системой,
подлежит проверке по исходному файлу рапорта.

- [ ] Пять произвольно выбранных показателей карточки отчётных суток совпадают со значениями в файле рапорта.
- [ ] Раздел «Откуда цифры» содержит для каждого показателя адрес ячейки, диапазон суммирования либо формулу расчёта.
- [ ] Потери добычи отмечены признаком «расч.» и сопровождаются перечнем слагаемых.
- [ ] Сумма слагаемых равна отображаемому итоговому значению.

## 4. Материалы доклада

- [ ] Кнопка «Скачать презентацию» формирует файл формата `.pptx`.
- [ ] Презентация содержит одиннадцать слайдов в согласованном порядке.
- [ ] Значения показателей на слайдах совпадают с карточкой отчётных суток.
- [ ] Файл открывается в Microsoft PowerPoint без предупреждений.
- [ ] Диаграмма на слайде «Потенциал» доступна для редактирования средствами PowerPoint, то есть является диаграммой, а не изображением.
- [ ] При сборке образа с параметром `WITH_PDF=1` кнопка «PDF» формирует файл PDF. При `WITH_PDF=0` выводится сообщение о недоступности преобразования; повреждённый файл не формируется.

### 4.1. Листы формата А3

- [ ] Кнопка «Лист А3» в карточке отчётных суток формирует одну страницу формата А3 в альбомной ориентации.
- [ ] Состав листа отчётных суток совпадает с составом презентации за исключением одиннадцатого слайда: замечания к исходным данным и перечень расчётных величин на лист не выносятся.
- [ ] Выдача презентации доклада после формирования листа не изменяется: файл презентации совпадает с полученным ранее.
- [ ] Кнопка «Лист А3» в разделе «Сводки» формирует страницу формата А3 с показателями выбранного периода.
- [ ] Указание полноты данных размещено на листе аналитики выше показателей.
- [ ] На листе аналитики за период с пропущенными сутками диаграмма добычи содержит разрыв ряда; пропущенные сутки не смыкаются.
- [ ] Лист аналитики за год выводится суммами по месяцам; месяцы, за которые данные отсутствуют, остаются незаполненными.
- [ ] На обоих листах таблицы и заголовки не перекрываются, ни один элемент не выходит за край страницы.
- [ ] Выдача каждого листа зарегистрирована в журнале выдач.

## 5. Полнота данных

- [ ] В перечне отчётных суток пропуски выделены отдельными строками с указанием количества отсутствующих суток.
- [ ] Сводка за месяц с пропусками содержит указание «Данные неполные» и перечень отсутствующих дат.
- [ ] Сводка за квартал, содержащий данные только за один месяц, полной не считается.
- [ ] Сводка за период, начало которого не наступило, отмечается как не начавшийся период и полной не считается.
- [ ] Показатели не наступившего периода выводятся прочерками; диаграмма за такой период не строится.
- [ ] Перечень отсутствующих суток при большом их количестве заменяется указанием отрезка, за который данные имеются.

## 6. Сводные показатели

- [ ] Переключение периодов (неделя, месяц, квартал, полугодие, год) изменяет состав показателей.
- [ ] Произвольный период задаётся двумя датами.
- [ ] Сумма добычи за полный месяц совпадает с нарастающим итогом рапорта за последние отчётные сутки месяца в пределах погрешности округления.
- [ ] На графике суточной добычи отсутствующие сутки отображаются разрывом линии.
- [ ] Произвольный период продолжительностью свыше двух лет сокращается с выводом сообщения.

## 7. Сопоставление смежных суток

- [ ] Раздел «Качество данных» содержит замечания, выявленные при сопоставлении смежных отчётных суток.
- [ ] Количество замечаний за месяц исчисляется единицами, что обеспечивает их практическую применимость.
- [ ] Отметка «Разобрано» исключает замечание из перечня требующих внимания, не удаляя его из системы.
- [ ] Пользователю с ролью «Руководство» отметка «Разобрано» недоступна.

## 8. История скважин

- [ ] Раздел «Скважины» содержит перечень, упорядоченный по накопленным потерям добычи.
- [ ] Отбор по месторождению и по номеру скважины выполняется.
- [ ] В карточке скважины последовательные сутки простоя объединены в единый период.
- [ ] Сведения об остановках вскоре после ремонта сопровождаются указанием на то, что вывод о связи с ремонтом системой не формируется.

## 9. Устойчивость к изменению формы рапорта

Проверка механизма разметки.

- [ ] В копии файла рапорта изменён текст подписи строки; файл загружен.
- [ ] Отчётные сутки получили состояние «Требует подтверждения», показатель включён в раздел «Разметка».
- [ ] Страница подтверждения отображает фрагмент листа с выделением и содержит предложенные варианты.
- [ ] После указания ячейки и повторной загрузки состояние снято, значение показателя соответствует исходному файлу.
- [ ] Загрузка неизменённого файла рапорта после сохранения правила даёт прежний результат: правило на разбор не влияет.

## 10. Защита персональных данных

- [ ] В базе данных отсутствует текст обращений в здравпункт; хранится только их количество.
- [ ] В базе данных отсутствует описание происшествия; хранятся дочернее общество, месторождение, область события и тип.
- [ ] Автоматические проверки, закрепляющие указанные требования, выполнены и пройдены.

Проверки выполняются из каталога с исходным кодом, на рабочем месте
разработчика или администратора. В состав образа средства
тестирования не входят.

```bash
python -m pytest tests/test_decks.py tests/test_models.py -q
```

## 11. Регистрация действий

- [ ] Журнал выдач содержит сведения о том, кем и когда выгружены презентация, лист формата А3 либо исходный файл рапорта.
- [ ] Журнал поправок разметки содержит автора, время и основание.
- [ ] Очистка журналов средствами интерфейса не предусмотрена.

## 12. Эксплуатационные характеристики

- [ ] Перезапуск узла приводит к автоматическому запуску всех служб.
- [ ] Резервное копирование выполняется по расписанию.
- [ ] Восстановление из резервной копии проверено на отдельном узле; данные восстановлены в полном объёме.
- [ ] Администратору системы известен порядок получения журналов каждой службы.
- [ ] Сообщения об ошибках (400, 403, 404, 500, 502) отображаются на русском языке и содержат указание на необходимые действия.

## 13. Эксплуатационная документация

- [ ] Раздел «Инструкция» доступен из главного меню всем пользователям.
- [ ] Руководство содержит разделы для работника промысла, руководства и администратора системы.
- [ ] Функция печати формирует документ в формате PDF, пригодный для передачи.

## Ограничения системы

Перечисленные положения являются принятыми проектными решениями
и не относятся к недостаткам. Приёмочная комиссия уведомляется о них
до начала испытаний.

1. **Поиск показателей основан на текстах подписей.** Изменение
   подписи обрабатывается при условии, что синоним внесён через
   редактор разметки либо в схему разбора. В противном случае
   используется эталонный адрес ячейки с выводом предупреждения;
   принятие неверного значения без уведомления исключено.
2. **Процент утилизации попутного нефтяного газа не является
   измеряемой величиной.** В рапорте он постоянен: объём сжигания
   определяется от объёма добычи по нормативу. В связи с этим
   в сводных показателях приводятся добыча и сжигание в тоннах.
   Запрос в ЦИТУ о порядке определения объёма сжигания направлен,
   ответ не получен.
3. **Групповые записи не распределяются по скважинам.** Строки вида
   «76 скважин» хранятся отдельно, поскольку состав скважин
   в рапорте не указан.
4. **Сведения об остановках вскоре после ремонта носят характер
   наблюдения.** В их число входят плановые состояния: вывод
   на кривую восстановления давления, технологические ограничения.
5. **Исходные файлы рапортов хранятся в полном объёме.** Хранение
   необходимо для повторного разбора и формирования презентаций.
   Из этого следует, что персональные данные присутствуют в файловом
   хранилище системы, не присутствуя в базе данных. Решение
   о порядке хранения принимается владельцем данных.
