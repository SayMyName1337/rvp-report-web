# Развёртывание

Порядок установки «Суточного рапорта» на сервер. Рассчитано на того,
кто видит систему впервые: всё, что нужно знать, есть здесь.

## Что понадобится

- узел с Linux, 2 ядра, 4 ГБ памяти, 40 ГБ диска;
- Docker версии 24 и новее с плагином Compose;
- сертификат TLS на имя узла — внутреннего удостоверяющего центра
  достаточно;
- доступ к репозиторию с кодом.

Данных немного: около ста тысяч строк в базе и ста мегабайт файлов
рапортов за год. Сорока гигабайт хватит на годы вперёд вместе
с резервными копиями.

## Установка

### 1. Забрать код

```bash
sudo mkdir -p /opt/rvp-report && sudo chown "$USER" /opt/rvp-report
git clone <адрес репозитория> /opt/rvp-report
cd /opt/rvp-report
```

### 2. Настроить окружение

```bash
cp .env.example .env
```

Открыть `.env` и задать:

| Переменная | Что писать |
|---|---|
| `DJANGO_SETTINGS_MODULE` | `config.settings.prod` |
| `DJANGO_SECRET_KEY` | длинная случайная строка, см. ниже |
| `DJANGO_ALLOWED_HOSTS` | имя узла, например `rapport.company.ru` |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | `https://rapport.company.ru` |
| `POSTGRES_DB`, `POSTGRES_USER` | `rvp`, `rvp` |
| `POSTGRES_PASSWORD` | длинный случайный пароль |
| `WITH_PDF` | `1`, либо `0`, если перевод в PDF не нужен |

Ключ и пароль получить так:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(64))"
```

Файл `.env` содержит пароли: он не должен попадать в репозиторий
и должен быть доступен только владельцу.

```bash
chmod 600 .env
```

### 3. Положить сертификат

```bash
mkdir -p deploy/tls
cp <ваш сертификат> deploy/tls/server.crt
cp <ваш ключ>       deploy/tls/server.key
chmod 600 deploy/tls/server.key
```

### 4. Запустить

```bash
docker compose -f deploy/compose.yaml --env-file .env up -d --build
```

Первая сборка занимает несколько минут. Образ без LibreOffice весит
около 575 МБ, с ним — примерно вдвое больше.

Данные в образ не попадают: за этим следит `.dockerignore`. Образ —
это код, рапорты и хранилище файлов приходят в него томами. Если
однажды сборка начнёт идти заметно дольше обычного, первым делом
проверьте этот файл: в прошлый раз получасовая сборка оказалась
именно симптомом того, что в контекст затесалось лишнее.

Приложение само выполнит миграции, соберёт статику и создаст роли.
Проверить:

```bash
docker compose -f deploy/compose.yaml --env-file .env ps
docker compose -f deploy/compose.yaml --env-file .env logs -f web
```

### 5. Завести администратора

```bash
docker compose -f deploy/compose.yaml --env-file .env \
    run --rm web manage createsuperuser
```

Пароль задаёт человек, который разворачивает систему. В коде,
в файлах настроек и в переменных окружения паролей быть не должно.

### 6. Раздать доступ

Зайти на `https://<имя узла>/admin/` и завести учётные записи.
У каждого работника своя: общих входов в системе нет, иначе журнал
действий теряет смысл.

Роли назначаются группами:

| Роль | Кому |
|---|---|
| Администраторы | сопровождение системы |
| Руководство | главный инженер и выше |
| Работники промысла | начальник ЦИТУ и его заместитель |

**Роль «Работники промысла» выдать минимум двоим.** Если загружать
рапорты может только один человек, в первый же его отпуск в истории
появится дыра, а дыры портят все сводки за период.

### 7. Загрузить архив

Если накопились рапорты за прошлые месяцы, залить их сразу: сводки
и дашборд имеют смысл только на истории.

```bash
docker compose -f deploy/compose.yaml --env-file .env \
    run --rm -v /путь/к/рапортам:/data web manage load_reports /data
```

После загрузки разобрать справочники: незнакомые написания
месторождений заводятся автоматически и помечаются для проверки.

```bash
docker compose -f deploy/compose.yaml --env-file .env \
    run --rm web manage link_aliases          # показать догадки
docker compose -f deploy/compose.yaml --env-file .env \
    run --rm web manage link_aliases --apply  # применить
```

После применения синонимов рапорты нужно загрузить заново: команда
об этом напомнит.

### 8. Включить HSTS

Только **после** того, как сертификат заработал устойчиво. Указание
браузеру ходить сюда исключительно по защищённому протоколу действует
заданный срок, и ошибочно включённый заголовок закрывает доступ к сайту
на всё это время.

В `.env`:

```
DJANGO_HSTS_SECONDS=31536000
```

и перезапустить `web`.

## Резервное копирование

```bash
crontab -e
```

```
0 3 * * * /opt/rvp-report/deploy/backup.sh >> /var/log/rvp-backup.log 2>&1
```

Копируются база и хранилище файлов, копии старше тридцати суток
удаляются. Каталог задаётся переменной `BACKUP_DIR`, срок хранения —
`BACKUP_KEEP_DAYS`.

### Восстановление

```bash
# база
docker compose -f deploy/compose.yaml --env-file .env exec -T db \
    pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --clean --if-exists \
    < deploy/backup/db_2026-09-11_0300.dump

# файлы
docker compose -f deploy/compose.yaml --env-file .env \
    run --rm -v "$PWD/deploy/backup:/backup" web \
    tar xzf /backup/media_2026-09-11_0300.tar.gz -C /app/media
```

**Проверять восстановление надо не тогда, когда оно понадобилось.**
Раз в квартал разверните копию в стороне и убедитесь, что данные
на месте. Непроверенная копия — это не копия.

## Обновление

```bash
cd /opt/rvp-report
git pull
docker compose -f deploy/compose.yaml --env-file .env up -d --build
```

Миграции выполняются при запуске. Перед обновлением сделайте копию:

```bash
./deploy/backup.sh
```

## Ежедневная работа

Фоновых задач в системе нет: разбор рапорта и сборка презентации идут
в самом запросе. Если загрузка не удалась, об этом скажет протокол
на странице загрузки, а подробности будут в журнале приложения:

```bash
docker compose -f deploy/compose.yaml --env-file .env logs -f web
```

Сверка суток с соседними выполняется при загрузке. Пересчитать
за отрезок дат:

```bash
docker compose -f deploy/compose.yaml --env-file .env \
    run --rm web manage crosscheck --from 2026-08-01 --to 2026-08-31
```

## Если что-то пошло не так

Страницы ошибок написаны так, чтобы по ним можно было сориентироваться
и без администратора: каждая говорит, что случилось и что делать.
Пользователь назовёт код — по нему видно, куда смотреть.

| Признак | Что смотреть |
|---|---|
| Страница не открывается | `logs nginx`, сертификат в `deploy/tls` |
| «Приложение сейчас недоступно» (502) | `logs web`: служба не поднялась или упала |
| «Сбой в приложении» (500) | `logs web`, запись за то время, которое назвал пользователь |
| Рапорт загружен, данных нет | протокол на странице загрузки, затем `logs web` |
| Разбор берёт не те ячейки | раздел «Разметка» в интерфейсе |
| Сводка меньше ожидаемой | полнота данных на странице сводки |
| PDF не собирается | собран ли образ с `WITH_PDF=1` |

## Чего в контуре не происходит

Полезно для разговора со службой информационной безопасности:

- приложение **не обращается в интернет**: библиотеки ставятся при
  сборке образа, Chart.js лежит в репозитории, внешние CDN
  не используются;
- **нет исполняемого кода в данных**: читается `.xlsx`, создаётся
  `.pptx` — форматы без макросов; загружаемые файлы проверяются
  по расширению, сигнатуре и размеру;
- **персональные данные в базу не попадают**: ни текст обращений
  в здравпункт, ни описание происшествия;
- **файлы не отдаются веб-сервером напрямую**: скачивание идёт через
  представление с проверкой прав и записью в журнал выдач;
- приложение работает **не от суперпользователя** внутри контейнера;
- наружу смотрит только nginx; база порт не публикует.
