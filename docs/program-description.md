# Описание программы

Информационная система «Суточный рапорт». ООО «СК Русвьетпетро».
Редакция от 16.09.2026.

Документ составлен в соответствии с требованиями ГОСТ 19.402-78
«Описание программы» и содержит сведения о логической структуре
и функционировании программы.

## 2. Функциональное назначение

### 2.1. Классы решаемых задач

Программа предназначена для автоматизации обработки суточных рапортов
ЦИТУ и подготовки материалов ежедневного доклада главному инженеру.

Реализованы следующие функции:

1. Приём файла суточного рапорта в формате Microsoft Excel (.xlsx),
   контроль его пригодности и извлечение показателей.
2. Хранение показателей за произвольное число отчётных суток
   с сохранением исходных файлов.
3. Регистрация происхождения каждого показателя: адреса ячейки,
   диапазона суммирования либо формулы расчёта.
4. Контроль качества исходных данных: выявление противоречий внутри
   рапорта и отклонений при сопоставлении со смежными отчётными
   сутками.
5. Формирование сводных показателей за неделю, месяц, квартал,
   полугодие, год и произвольный период с указанием полноты данных.
6. Формирование презентации доклада в форматах PowerPoint и PDF.
7. Формирование листов формата А3 для печати: отчётных суток
   и аналитики за период.
8. Ведение истории эксплуатации скважин.
9. Настройка правил поиска показателей при изменении формы рапорта
   (редактор разметки).
10. Разграничение доступа по должностным ролям и регистрация выдачи
    файлов.
11. Ограничение количества последовательных неудачных попыток входа.

### 2.2. Функциональные ограничения

1. Единственным источником данных является файл суточного рапорта.
   Досчёт отсутствующих показателей не выполняется. Показатели,
   вычисляемые программой, отмечаются признаком «расч.»
   и сопровождаются формулой расчёта.
2. Исправления в исходные данные не вносятся. Выявленные противоречия
   выводятся в виде замечаний.
3. Сводные показатели за период с отсутствующими отчётными сутками
   сопровождаются указанием количества учтённых суток и не подлежат
   сопоставлению с полными периодами.
4. Персональные данные в базу данных не помещаются. Текст обращений
   в здравпункт и описание происшествия не сохраняются; хранятся
   количественные и обезличенные признаки.
5. Строки рапорта, относящиеся к нескольким скважинам одновременно,
   в историю отдельной скважины не включаются.
6. Рассылка уведомлений не предусмотрена.
7. Продолжительность произвольного периода сводки ограничена двумя
   годами.
8. Одновременная работа рассчитана на подразделение предприятия;
   нагрузочное тестирование на большее число пользователей
   не проводилось.

## 3. Описание логической структуры

### 3.1. Состав программы

![Состав системы и взаимодействие компонентов](img/architecture.svg)

Программа построена по трёхзвенной схеме. Обращения пользователя
поступают по защищённому протоколу на сервер nginx, который завершает
TLS-соединение, отдаёт статические файлы и передаёт остальные запросы
приложению по внутренней сети контейнеров. Приложение обращается
к базе данных и файловому хранилищу. Сетевой доступ извне имеет
только nginx; порт базы данных не публикуется.

Приложение разделено на функциональные части:

| Часть | Выполняемые функции |
|---|---|
| `accounts` | учётные записи, роли, вход в систему, смена пароля |
| `catalog` | справочники: месторождения, скважины, объекты ППД, узлы учёта, резервуары, подрядчики, причины простоя |
| `reports` | приём файла, разбор, хранение показателей отчётных суток, страницы суток |
| `analytics` | сводные показатели за период, дашборд, сопоставление смежных суток, лист аналитики формата А3 |
| `layout` | редактор разметки: правила поиска показателей |
| `decks` | формирование презентации и листа отчётных суток, их выдача, журнал выдач |
| `guide` | руководство пользователя |
| `rvp_report` | механизм разбора книги Excel и формирования слайдов и листов |

Часть `rvp_report` перенесена из ранее разработанной настольной
программы и не зависит от каркаса приложения. Такое разделение
позволяет использовать один и тот же проверенный механизм разбора
и в настольной, и в веб-версии.

### 3.2. Используемые методы

**Поиск показателей по текстовым подписям.** Положение показателя
в книге Excel определяется не адресом ячейки, а текстом подписи строки
и заголовка столбца. Блок рапорта отыскивается по заголовку раздела,
внутри блока — требуемая строка, затем требуемый столбец. Вставка
строк и столбцов, а также смещение блоков на результат разбора
не влияют.

При отсутствии показателя по подписи применяется эталонный адрес
ячейки, зафиксированный при разработке; отчётные сутки при этом
получают состояние «Требует подтверждения», а показатель включается
в перечень, подлежащий уточнению оператором. Принятие значения без
уведомления исключено.

**Правила разметки.** Оператор указывает ячейку, содержащую
требуемый показатель, после чего программа формирует правило поиска:
по подписи строки, по заголовку столбца либо по адресу ячейки.
Правило применяется только в том случае, если показатель
не обнаружен по основной подписи, то есть носит дополняющий, а не
замещающий характер.

**Регистрация происхождения показателей.** При разборе для каждого
показателя сохраняется способ его получения. Значения, вычисленные
программой, содержат формулу расчёта.

**Контроль смежных суток.** Показатели отчётных суток сопоставляются
с показателями предшествующих суток по четырём правилам: резкое
изменение относительно предыдущих суток, отклонение от привычного
уровня за четырнадцать суток, неизменность значения на протяжении
нескольких суток, расхождение направления изменения фонда и добычи.

Правило отклонения от уровня опирается на фактический разброс
значений за предшествующие четырнадцать суток, вычисляемый при
каждой проверке. Пороговые множители и предельные доли изменения
для каждого показателя заданы постоянными величинами в коде;
их значения подобраны по массиву рапортов за месяц так, чтобы
количество выявляемых отклонений оставалось обозримым.

### 3.3. Порядок обработки суточного рапорта

![Обработка суточного рапорта](img/dataflow.svg)

Обработка выполняется в рамках одного запроса и включает следующие
этапы:

1. **Контроль файла.** Последовательно проверяются расширение, размер,
   сигнатура и внутренняя структура книги, а также совпадение
   с ранее загруженными файлами. Проверки выполняются в порядке
   возрастания трудоёмкости. Файл, не прошедший контроль, к разбору
   не принимается; ранее принятые данные сохраняются без изменений.
2. **Сохранение файла.** Пригодный файл помещается в файловое
   хранилище, создаётся запись в истории загрузок.
3. **Разбор.** Выполняется поиск показателей по подписям с учётом
   действующих правил разметки. Результатом является модель суточного
   рапорта в оперативной памяти, а также перечень замечаний
   и перечень показателей, принятых по эталонному адресу.
4. **Запись в базу данных.** Показатели, журнал происхождения,
   замечания и новые записи справочников записываются одной
   транзакцией. Данные за отчётную дату замещаются целиком, что
   обеспечивает идемпотентность повторной загрузки.
5. **Сопоставление со смежными сутками.** Выполняется после записи,
   поскольку требует наличия истории.
6. **Формирование протокола.** Пользователю выводятся сведения
   о принятых данных, замещении ранее принятых данных, замечаниях
   и показателях, требующих подтверждения.

Презентация доклада формируется разбором исходного файла, минуя базу
данных. Такой порядок обеспечивает соответствие слайдов файлу,
проверенному пользователем, и исключает прохождение сведений
ограниченного доступа через хранилище системы.

### 3.4. Структура хранимых данных

Основной единицей хранения является запись отчётных суток, с которой
связаны показатели по разделам рапорта: добыча и сдача нефти,
состояние фонда скважин, потери добычи и их причины, поддержание
пластового давления, резервуарный парк, качество товарной нефти,
попутный нефтяной газ, энергетика, бурение, очистка трубопроводов,
промышленная безопасность.

Отдельно хранятся: история загрузок файлов, журнал происхождения
показателей, замечания к исходным данным, результаты сопоставления
смежных суток, правила разметки, журнал выдачи файлов, справочники
и учётные записи.

Записи справочников, созданные автоматически при разборе, отмечаются
как требующие проверки администратором.

### 3.5. Разграничение доступа

Права определяются принадлежностью учётной записи к группе.

| Группа | Предоставляемые права |
|---|---|
| Администраторы | полный доступ, включая справочники, учётные записи и повторный разбор архива |
| Руководство | просмотр показателей отчётных суток и сводных показателей, выгрузка презентаций |
| Работники промысла | загрузка и повторная загрузка рапортов, работа с разметкой, а также права группы «Руководство» |

Доступ без прохождения аутентификации не предоставляется ни к одной
странице, кроме формы входа. Самостоятельная регистрация
не предусмотрена. Выданный пароль подлежит замене при первом входе.

Выгрузка исходного файла рапорта доступна группам «Работники
промысла» и «Администраторы»; каждая выгрузка регистрируется
в журнале с указанием пользователя, файла и времени.

**Ограничение количества попыток входа.** Количество последовательных
неудачных попыток входа ограничено. По исчерпании установленного
количества вход закрывается на установленный срок; вместо формы входа
выводится сообщение с указанием срока и порядка досрочного снятия
блокировки.

| Параметр | Значение по умолчанию | Переменная окружения |
|---|---|---|
| Допустимое количество неудачных попыток | 5 | `AXES_FAILURE_LIMIT` |
| Срок блокировки, минут | 15 | `AXES_COOLOFF_MINUTES` |

Блокируется сочетание учётной записи и сетевого адреса, а не каждый
из них по отдельности. Блокировка по сетевому адресу закрыла бы доступ
всем работникам предприятия, обращающимся через общий внешний адрес.
Блокировка по имени учётной записи допускала бы преднамеренное закрытие
доступа работнику посторонним лицом.

Успешный вход обнуляет счётчик неудачных попыток. Попытки, выполненные
в течение действия блокировки, срок её действия не изменяют. Досрочное
снятие блокировки выполняется администратором системы.

Неудачные попытки регистрируются с указанием учётной записи, сетевого
адреса и времени. Сетевой адрес обратившегося определяется по заголовку,
устанавливаемому обратным прокси-сервером; заголовок принимается
во внимание только при соответствующем параметре конфигурации.

### 3.6. Связь с другими программами

Программного взаимодействия с иными системами предприятия
не предусмотрено. Обмен данными выполняется файлами: входной файл
суточного рапорта готовится в Microsoft Excel, выходная презентация
открывается в Microsoft PowerPoint.

## 5. Вызов и загрузка

### 5.1. Запуск программы

Программа поставляется в виде образов контейнеров и запускается
средствами Docker Compose:

```bash
docker compose -f deploy/compose.yaml --env-file .env up -d --build
```

Состав служб: `nginx` — приём обращений и завершение TLS; `web` —
приложение; `db` — база данных.

При запуске службы `web` последовательно выполняются: ожидание
готовности базы данных, применение миграций, сборка статических
файлов, создание групп ролей, запуск сервера приложения.

Параметры среды задаются файлом `.env`; состав параметров приведён
в файле `.env.example`. Хранение паролей в исходном коде и в файлах
настроек не допускается.

### 5.2. Обращение пользователя

Обращение выполняется браузером по адресу `https://<имя узла>`.
Обращение по незащищённому протоколу перенаправляется на защищённый.

### 5.3. Команды управления

| Команда | Назначение |
|---|---|
| `manage.py load_reports <каталог>` | массовая загрузка и повторный разбор архива рапортов |
| `manage.py link_aliases [--apply]` | сопоставление сокращённых наименований месторождений |
| `manage.py crosscheck --from <дата> --to <дата>` | повторное сопоставление смежных суток за интервал |
| `manage.py setup_roles` | создание групп ролей |
| `manage.py createsuperuser` | создание учётной записи администратора |

## 6. Входные данные

### 6.1. Характер и организация

Входными данными является файл суточного рапорта — книга Microsoft
Excel, подготавливаемая начальником ЦИТУ. Книга содержит лист
установленной формы с разделами по направлениям деятельности.

| Параметр | Значение |
|---|---|
| Формат | Microsoft Excel Open XML (.xlsx) |
| Типовой размер | около 300 КБ |
| Предельный размер | 25 МБ (задаётся параметром `MAX_UPLOAD_SIZE_MB`) |
| Периодичность | одни сутки — один файл |

Формат .xls (Microsoft Excel версий до 2007 года) не поддерживается.

### 6.2. Предварительная подготовка

Предварительная подготовка файла средствами программы не требуется.
Требования к содержанию файла: наличие листа суточного рапорта
и заполненных подписей разделов, строк и столбцов. Изменение состава
и порядка строк допускается; изменение текстов подписей обрабатывается
средствами редактора разметки.

### 6.3. Контроль входных данных

| Проверка | Отклоняемое условие |
|---|---|
| Расширение | расширение, отличное от .xlsx |
| Размер | нулевой размер либо превышение предельного |
| Сигнатура | несоответствие содержимого формату |
| Структура | нарушение структуры книги |
| Повтор | полное совпадение с ранее загруженным файлом без пояснения |

## 7. Выходные данные

### 7.1. Экранные формы

Показатели отчётных суток, сводные показатели за период, история
эксплуатации скважин, сведения о происхождении показателей, результаты
контроля качества данных, история загрузок, журнал выдачи файлов,
руководство пользователя.

Числовые значения выводятся в русской записи: разряды разделяются
неразрывным пробелом, дробная часть — запятой. Отсутствующее значение
обозначается прочерком и не подменяется нулём.

### 7.2. Файлы

| Файл | Формат | Состав |
|---|---|---|
| Презентация доклада | .pptx | одиннадцать слайдов согласованного состава |
| Презентация доклада | .pdf | то же, преобразование средствами LibreOffice |
| Лист отчётных суток | .pptx, .pdf | показатели первых десяти слайдов доклада на одной странице формата А3 |
| Лист аналитики за период | .pptx, .pdf | сводные показатели за период на одной странице формата А3 |
| Исходный файл рапорта | .xlsx | ранее загруженный файл без изменений |

Листы формата А3 предназначены для печати и рассылки. Состав листа
отчётных суток совпадает с составом презентации доклада за исключением
одиннадцатого слайда, содержащего служебные сведения о качестве
исходных данных. Презентация доклада при этом не изменяется: лист
формируется отдельным файлом.

Лист аналитики за период в первой строке содержит указание полноты
данных: количество учтённых отчётных суток из числа ожидаемых.
Диаграмма добычи строится по календарю периода — отсутствующие
отчётные сутки остаются разрывом ряда. Период продолжительностью
свыше тридцати одних суток выводится суммами по месяцам.

Файлы не отдаются веб-сервером напрямую: выгрузка выполняется
приложением с проверкой прав доступа и регистрацией в журнале выдач.

### 7.3. Сообщения программы

Сообщения выводятся на русском языке и содержат указание на характер
несоответствия и требуемые действия. Перечни сообщений, выводимых
при загрузке суточного рапорта и при входе в систему, приведены
в руководстве пользователя (раздел «Инструкция» интерфейса системы),
раздел 13.
