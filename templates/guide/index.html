1. Назначение программы

Информационная система «Суточный рапорт» предназначена для приёма, хранения и анализа суточных рапортов центральной инженерно-технологической службы (ЦИТУ) ООО «СК Русвьетпетро», а также для формирования презентационных материалов к ежедневному докладу главному инженеру.

Система обеспечивает выполнение следующих функций:

  • приём файла суточного рапорта в формате Microsoft Excel (.xlsx) и извлечение из него показателей;
  • хранение показателей за произвольное число отчётных суток с сохранением исходных файлов;
  • формирование сводных показателей за неделю, месяц, квартал, полугодие, год и произвольный период;
  • формирование презентации доклада в формате PowerPoint (.pptx) и PDF;
  • формирование листов формата А3 для печати: отчётных суток и аналитики за период;
  • ведение истории эксплуатации скважин;
  • контроль качества исходных данных, в том числе сопоставление показателей смежных отчётных суток;
  • разграничение доступа по должностным ролям и регистрацию действий пользователей.

Единственным источником данных является файл суточного рапорта, загруженный пользователем. Система не выполняет досчёта показателей и не использует внешних источников. Показатели, отсутствующие в рапорте и вычисляемые системой, отмечаются признаком «расч.» и сопровождаются формулой расчёта.

2. Условия выполнения программы

Работа с системой выполняется в браузере. Требуется браузер актуальной версии с поддержкой HTML5 и CSS3: Яндекс Браузер, Google Chrome, Mozilla Firefox. Установка программного обеспечения на рабочее место не требуется.

Доступ к системе предоставляется по защищённому протоколу HTTPS из корпоративной сети предприятия. Обращение к внешним информационным ресурсам системой не производится.

Для работы необходима персональная учётная запись. Учётные записи создаются администратором системы; самостоятельная регистрация не предусмотрена.

{# --- 3 ---------------------------------------------------------- #}

3. Вход в систему

3.1. Порядок входа

  1. Открыть в браузере адрес системы.
  2. Ввести имя пользователя и пароль, выданные администратором системы.
  3. Нажать кнопку «Войти».

3.2. Смена пароля

При первом входе система требует замены выданного пароля. До выполнения замены переход к разделам системы блокируется.

Смена пароля в дальнейшем выполняется на странице «Смена пароля». Пароль должен содержать не менее десяти символов и не должен совпадать с именем пользователя или быть на него похожим.

Восстановление пароля по электронной почте не предусмотрено. При утрате пароля следует обратиться к администратору системы для назначения нового.

3.3. Ограничение количества попыток входа

После пяти подряд неверно введённых паролей вход для данной учётной записи с данного рабочего места закрывается на пятнадцать минут. Вместо формы входа выводится страница с указанием срока. Мера установлена для исключения подбора пароля.

ОбстоятельствоРезультат
Верный пароль введён до исчерпания попыток Вход выполняется, счётчик неудачных попыток обнуляется.
Попытки исчерпаны Вход закрыт на пятнадцать минут, в том числе при вводе верного пароля.
Повторные попытки во время блокировки Срок не продлевают и не сокращают.
Ошибка допущена другим работником На вход остальных работников не влияет: закрывается сочетание учётной записи и рабочего места, а не рабочее место целиком.

Ожидание не требуется, если пароль забыт: администратор системы назначает новый пароль и снимает блокировку немедленно (раздел 12.1).

{# --- 4 ---------------------------------------------------------- #}

4. Загрузка суточного рапорта работник промысла

4.1. Требования к загружаемому файлу

ПараметрЗначение
Формат книга Microsoft Excel, расширение .xlsx
Предельный размер 25 МБ (типовой размер рапорта — около 300 КБ)
Предельный размер в развёрнутом виде 500 МБ (типовой рапорт разворачивается примерно в 4 МБ)
Состав лист суточного рапорта установленной формы

Формат .xls (Microsoft Excel версий до 2007 года) не поддерживается. Файл в этом формате следует предварительно пересохранить средствами Microsoft Excel как «Книга Excel (*.xlsx)».

4.2. Порядок загрузки

  1. Перейти в раздел «Загрузить» главного меню. Раздел доступен пользователям с ролью «Работник промысла» и администратору системы.
  2. Поместить файл рапорта в область загрузки перетаскиванием либо выбрать файл в стандартном диалоге, нажав на область загрузки.
  3. При повторной загрузке за те же отчётные сутки заполнить поле «Пояснение» (см. п. 4.4). В остальных случаях поле не заполняется.
  4. Нажать кнопку «Загрузить». Обработка файла занимает несколько секунд; на это время кнопка блокируется для исключения повторной отправки.
  5. Дождаться отображения протокола разбора и проверить его содержимое (п. 4.3).

4.3. Протокол разбора

По завершении обработки система отображает протокол разбора, содержащий сведения о принятых данных.

Показатель протокола Содержание
Отчётная дата Дата, за которую приняты данные. Подлежит проверке в первую очередь: несоответствие даты означает загрузку другого файла.
Скважин в списках Количество обработанных строк по скважинам (текущий простой, бездействие, внутрисменные потери, запуски).
Месторождений Количество месторождений, обнаруженных в блоке добычи.
Показателей с записанным происхождением Количество показателей, для которых сохранён источник значения.
Замечаний к данным Количество противоречий, обнаруженных в исходном файле.

При наличии выводятся дополнительные разделы протокола:

  • «Требуют подтверждения» — показатели, не обнаруженные по подписям (см. раздел 5);
  • «Сверка с соседними сутками» — отклонения, выявленные при сопоставлении со смежными отчётными сутками;
  • «Замечания к исходным данным» — противоречия внутри загруженного файла.

Замечания носят информационный характер. Исправления в исходные данные системой не вносятся.

4.4. Повторная загрузка за отчётные сутки

При загрузке рапорта за отчётные сутки, данные за которые уже приняты, ранее принятые данные замещаются полностью. Частичное объединение данных разных загрузок не производится.

Протокол разбора содержит сведения о замещении: наименование ранее загруженного файла, дату, время и пользователя, выполнившего загрузку. Замещённая загрузка сохраняется в разделе «История загрузок».

При повторной загрузке файла, полностью совпадающего с ранее загруженным, система запрашивает пояснение. Пояснение сохраняется в истории загрузок.

{# --- 5 ---------------------------------------------------------- #}

5. Показатели, не подтверждённые разбором работник промысла

5.1. Назначение механизма

Поиск показателей в файле рапорта выполняется по текстовым подписям строк и заголовкам столбцов, а не по адресам ячеек. Вставка строк и столбцов, а также смещение блоков рапорта на результат разбора не влияют.

При изменении текста подписи показатель по ней не обнаруживается. В этом случае система использует эталонный адрес ячейки, а отчётные сутки получают состояние «Требует подтверждения». Значение принимается в базу данных, но достоверность его не гарантируется.

5.2. Порядок подтверждения

  1. Перейти в раздел «Разметка» главного меню. Отображается перечень неподтверждённых показателей с указанием искомой подписи, использованного эталонного адреса и количества затронутых отчётных суток.
  2. Нажать кнопку «Указать ячейку». Отображается фрагмент листа рапорта в том виде, в котором его обрабатывает система.
  3. Выбрать ячейку, содержащую требуемый показатель. Система формирует правило поиска (по подписи строки, по заголовку столбца либо по адресу ячейки) и отображает получаемое значение.
  4. Подтвердить правило. Правило сохраняется и применяется при последующих загрузках.
  5. Для применения правила к ранее принятым отчётным суткам выполнить повторную загрузку соответствующих файлов.

5.3. Свойства правил

  • Правило применяется только в том случае, если показатель не обнаружен по основной подписи. При восстановлении прежней формы рапорта правило не применяется и на результат разбора не влияет.
  • Правило, привязанное к адресу ячейки, не переносит вставку строк. Система выводит соответствующее предупреждение при сохранении такого правила.
  • Все правила отображаются в разделе «Журнал поправок» с указанием автора и даты. Действие любого правила может быть отменено.
{# --- 6 ---------------------------------------------------------- #}

6. Данные отчётных суток

6.1. Перечень отчётных суток

Раздел «Суточные рапорты» содержит перечень отчётных суток, данные за которые приняты системой. Пропуски в последовательности дат выделяются отдельными строками с указанием количества отсутствующих суток.

6.2. Карточка отчётных суток

Переход по дате открывает карточку отчётных суток, содержащую показатели в составе разделов доклада: ключевые показатели, потери добычи и их причины, добыча по месторождениям, состояние фонда скважин, поддержание пластового давления, резервуарный парк, качество товарной нефти, попутный нефтяной газ, энергетика, бурение.

6.3. Происхождение показателей

Кнопка «Откуда цифры» в заголовке карточки открывает сведения о происхождении каждого показателя: адрес ячейки исходного файла, диапазон суммирования либо формулу расчёта. Функция предназначена для проверки достоверности показателей, в том числе в ходе доклада.

{# --- 7 ---------------------------------------------------------- #}

7. Презентация и лист А3

7.1. Презентация доклада

В карточке отчётных суток предусмотрены кнопки «Скачать презентацию» (формат .pptx) и «PDF». Состав и порядок одиннадцати слайдов согласованы с начальником ЦИТУ и изменению не подлежат.

Презентация формируется непосредственно из исходного файла рапорта, минуя базу данных. Такой порядок обеспечивает соответствие слайдов проверенному пользователем файлу и исключает прохождение сведений ограниченного доступа через хранилище системы.

Формирование презентации занимает около пяти секунд. Повторное обращение к ранее сформированной презентации выполняется без пересборки. При замещении данных за отчётные сутки презентация формируется заново.

Преобразование в PDF выполняется средствами LibreOffice и доступно, если система установлена в соответствующей конфигурации. При отсутствии преобразователя выводится сообщение; на выгрузку в формате PowerPoint это не влияет.

7.2. Лист отчётных суток формата А3

Кнопки «Лист А3» и «А3 в PowerPoint» формируют те же показатели на одной странице формата А3 в альбомной ориентации. Лист предназначен для печати и раздачи на совещании либо для пересылки файлом.

Состав листа совпадает с составом презентации доклада за исключением одиннадцатого слайда: приведённые на нём замечания к исходным данным и перечень величин, вычисленных программой, являются служебными и на лист не выносятся. Сведения о качестве данных приведены в разделе «Качество данных» интерфейса системы.

Презентация доклада при этом не изменяется: лист формируется отдельным файлом и на порядок выгрузки презентации не влияет.

{# --- 8 ---------------------------------------------------------- #}

8. Дашборд руководство

Начальная страница системы. Содержит показатели последних отчётных суток, динамику текущего месяца и итоговые показатели месяца.

В верхней части страницы размещены сведения о полноте и достоверности данных: количество отчётных суток с принятыми данными, перечень отсутствующих суток, количество неразобранных замечаний. Сведения подлежат учёту при использовании итоговых показателей.

ПризнакЗначение
Зелёная полоса сведений о данных Данные за период полные, замечания отсутствуют.
Жёлтая полоса сведений о данных Имеются отсутствующие отчётные сутки, неподтверждённые показатели либо неразобранные замечания. Состав приведён тут же.
Разрыв линии на графике Данные за соответствующие сутки отсутствуют. Интерполяция не выполняется.
Признак «расч.» Показатель вычислен системой. Слагаемые приведены в карточке отчётных суток.

9. Сводки за период

Раздел «Сводки» формирует показатели за неделю, месяц, квартал, полугодие, год либо произвольный период, задаваемый двумя датами. Периоды исчисляются по календарю: месяцем считается календарный месяц целиком. Такой порядок обеспечивает сопоставимость с нарастающими итогами, приведёнными в самом рапорте.

Сводка содержит следующие разрезы:

  • добыча по отчётным суткам;
  • потери добычи по составляющим и по причинам;
  • добыча по месторождениям;
  • скважины с наибольшими накопленными потерями;
  • баланс попутного нефтяного газа;
  • сверка суммы по суткам с нарастающим итогом рапорта.

Сводка за неполный период сопровождается указанием количества учтённых суток. Сопоставление таких сводок с полными периодами некорректно.

Продолжительность произвольного периода ограничена двумя годами. При задании большего периода он сокращается, о чём выводится сообщение.

Период, который ещё не наступил, отмечается как не начавшийся. Показатели за него выводятся прочерками: отсутствие данных не приравнивается к нулевым значениям.

9.1. Лист аналитики формата А3

Кнопки «Лист А3» и «А3 в PowerPoint» формируют показатели выбранного периода на одной странице формата А3 в альбомной ориентации.

В верхней части листа, до показателей, размещено указание полноты данных: количество учтённых отчётных суток из числа ожидаемых. Указание размещено первым намеренно — лист выдаётся файлом, и сумма за неполный период без такого указания подлежит ошибочному истолкованию как итог периода.

Диаграмма добычи строится по календарю периода: отсутствующие отчётные сутки остаются разрывом ряда и не смыкаются. Период продолжительностью свыше тридцати одних суток выводится суммами по месяцам; месяцы, за которые данные отсутствуют, остаются незаполненными.

Лист формируется при каждом обращении и в хранилище не помещается: сочетаний периодов неограниченное количество. Каждая выдача регистрируется в журнале.

{# --- 10 --------------------------------------------------------- #}

10. История скважины

Раздел «Скважины» содержит перечень скважин, упорядоченный по накопленным потерям добычи, с отбором по месторождению и по номеру. Переход по номеру скважины открывает историю её эксплуатации: периоды нахождения в каждом состоянии, причины остановок, накопленные потери, даты ремонтов.

Раздел «Остановки вскоре после ремонта» содержит случаи остановки скважины в течение 90 суток после даты последнего ремонта. Сведения носят характер наблюдения: в их число входят и плановые состояния (вывод на КВД, технологические ограничения). Вывод о связи остановки с ремонтом системой не формируется.

Номера скважин не уникальны в пределах предприятия. Скважина идентифицируется сочетанием месторождения и номера.

{# --- 11 --------------------------------------------------------- #}

11. Контроль качества данных

Система выполняет контроль данных двух видов.

Вид контроляВыявляемые отклонения
Контроль при загрузке Противоречия внутри файла рапорта: несоответствие суммы по списку итоговому значению, расхождение количества скважин между блоками, недостоверные даты.
Сопоставление смежных суток Отклонения, выявляемые только при сравнении со смежными отчётными сутками: резкое изменение показателя, неизменность показателя на протяжении нескольких суток, снижение добычи при увеличении действующего фонда.

Результаты контроля обоих видов отображаются в разделе «Качество данных».

Замечание, выявленное при сопоставлении смежных суток, может быть отмечено как разобранное кнопкой «Разобрано»: оно исключается из перечня требующих внимания, но из системы не удаляется. Отметка сохраняется и после повторной загрузки рапорта за эти сутки.

Замечания, выявленные при загрузке, отметке не подлежат: они относятся к содержанию файла и исчезают только после загрузки исправленного рапорта за те же отчётные сутки (см. п. 4.4). Внесение исправлений выполняется в файле средствами Microsoft Excel; система исходные данные не изменяет.

Замечание является основанием для проверки исходных данных и не является признаком ошибки системы.

12. Администрирование администратор системы

12.1. Учётные записи и роли

Управление учётными записями выполняется в разделе «Управление». Учётная запись создаётся вручную, права определяются включением в группу.

ГруппаДолжностное соответствие Предоставляемые права
Администраторы сопровождение системы полный доступ, включая справочники и учётные записи
Руководство главный инженер и выше дашборд, сводки, карточки отчётных суток, выгрузка презентаций
Работники промысла начальник ЦИТУ и его заместитель загрузка рапортов и разметка, а также права группы «Руководство»

Роль «Работники промысла» подлежит назначению не менее чем двум пользователям. При наличии единственного пользователя, уполномоченного загружать рапорты, его отсутствие приводит к пропускам в данных и нарушает сопоставимость сводок за период.

Досрочное снятие блокировки, установленной после исчерпания попыток входа (раздел 3.3), выполняется командой manage.py axes_reset_username <имя>. Перечень попыток входа и их адресов доступен в разделе «Управление», блок Axes; там же блокировка снимается удалением записи о попытках.

12.2. Справочники

Наименования месторождений в разных блоках рапорта приводятся в различных формах, включая сокращения. Неизвестные наименования создаются системой автоматически и отмечаются как требующие проверки. Сопоставление сокращений с основными наименованиями выполняется командой manage.py link_aliases: без параметров команда выводит предположения, с параметром --apply — применяет их.

12.3. Повторный разбор архива

Повторная обработка ранее загруженных рапортов выполняется командой manage.py load_reports <каталог>. Обработка идемпотентна по отчётной дате: данные за сутки замещаются полностью, дублирование исключено.

12.4. Резервное копирование

Резервное копирование базы данных и хранилища файлов выполняется сценарием deploy/backup.sh по расписанию. Копии со сроком хранения свыше установленного удаляются автоматически.

Восстановление из резервной копии подлежит проверке на отдельном узле не реже одного раза в квартал.

12.5. Диагностика

Сообщение, полученное пользователем Действия администратора
«Приложение сейчас недоступно» (502) Служба приложения не запущена либо завершилась аварийно. Проверить журнал службы web.
«Сбой в приложении» (500) Проверить журнал службы web за время, указанное пользователем.
«Эта страница не для вашей должности» (403) Пользователю не назначена требуемая роль. Проверить состав групп.
«Страница устарела, данные не отправлены» Истёк срок действия сеанса. Требуется повторный вход и повторная отправка формы. Вмешательства не требует.
«Такой страницы нет» (404) Некорректный адрес либо отсутствие данных за запрошенные отчётные сутки.

Порядок установки, обновления и восстановления системы приведён в документе «Развёртывание и сопровождение» (docs/deploy.md).

14. Ограничения программы

  1. Исправление исходных данных не выполняется. Выявленные противоречия выводятся в виде замечаний; изменения в файл рапорта и в принятые показатели системой не вносятся.
  2. Досчёт отсутствующих показателей не производится. Каждый показатель подлежит проверке по исходному файлу; вычисляемые величины отмечаются признаком «расч.» и сопровождаются формулой.
  3. Неполнота данных не сглаживается. Сводка за период с отсутствующими сутками сопровождается указанием количества учтённых суток и не может сопоставляться с полными периодами.
  4. Персональные данные в базу данных не помещаются. Текст обращений в здравпункт и описание происшествия не сохраняются; хранятся количественные и обезличенные признаки. Исходный файл рапорта сохраняется полностью и доступен для выгрузки пользователям с ролью «Работник промысла» и администратору системы; каждая выгрузка регистрируется.
  5. Обращение к внешним информационным ресурсам не производится. Система функционирует в пределах контура предприятия.
  6. Уведомления не рассылаются. Контроль своевременности загрузки суточного рапорта возлагается на пользователя.
  7. Групповые записи не распределяются по скважинам. Строки рапорта, относящиеся к нескольким скважинам одновременно, сохраняются отдельно и в историю отдельной скважины не включаются.
