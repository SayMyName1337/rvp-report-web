# Суточный рапорт — веб-приложение

Информационная система хранения и анализа суточных рапортов ЦИТУ
ООО «СК Русвьетпетро». Заменяет настольную программу подготовки
доклада: рапорт загружается через браузер, показатели накапливаются
в базе данных, формируются сводки за период, дашборд руководства
и презентация доклада в форматах PowerPoint и PDF.

## Состав системы

Реализованы: разграничение доступа по ролям, загрузка суточного
рапорта и массовая загрузка архива, перечень отчётных суток и карточка
суток со сведениями о происхождении показателей, редактор разметки,
формирование презентации и PDF, сводки за период, сопоставление
смежных суток, дашборд руководства, история скважин, руководство
пользователя, страницы сообщений об ошибках, средства развёртывания.

Механизм разбора проверен на 31 суточном рапорте за август
и 5 за июль 2026 года: показатели определяются по подписям, обращения
к эталонным адресам ячеек отсутствуют.

## Развёртывание для разработки

Требуются Python 3.12 и Docker.

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements/dev.txt
copy .env.example .env
```

В файле `.env` задать значение `DJANGO_SECRET_KEY`.

База данных разработки размещается в контейнере на порту **5442**:
порты 5432 и 5433 могут быть заняты экземплярами PostgreSQL,
установленными на рабочем месте.

```bash
docker compose -f deploy/compose.dev.yaml up -d
```

Применение миграций, создание ролей и учётной записи, запуск:

```bash
python manage.py migrate
python manage.py setup_roles
python manage.py createsuperuser
python manage.py runserver
```

Для просмотра страниц сообщений об ошибках отладочный режим
отключается, раздача статических файлов при этом сохраняется:

```bash
DJANGO_DEBUG=0 python manage.py runserver --insecure
```

## Проверки

```bash
python -m pycodestyle apps config tests rvp_report manage.py
python -m pytest tests -q --ignore=tests/test_parsing.py   # быстрые
python -m pytest tests/test_parsing.py -q                  # на файлах рапортов
```

Проверки разбора выполняются на действующих файлах рапортов. Каталог
задаётся переменной среды `RVP_REPORTS_DIR`, по умолчанию —
`data_august` в корне проекта. При отсутствии каталога эти проверки
пропускаются; остальные от наличия файлов не зависят.

Ограничение длины строки — 88 знаков, задано в `setup.cfg`. Русские
подписи схемы рапорта существенно длиннее английских идентификаторов,
и ограничение в 79 знаков приводило бы к переносам в ущерб
читаемости.

## Структура проекта

```
config/                 настройки, адреса, точки входа
    settings/           base, dev, prod — по средам
apps/
    accounts/           пользователи и роли
    catalog/            справочники: месторождения, скважины, объекты
    reports/            суточные рапорты: загрузка, разбор, хранение
    analytics/          сводки за период и дашборд
    decks/              формирование презентации
    guide/              руководство пользователя
rvp_report/             механизм разбора и формирования презентации
    domain/             модель рапорта, проверки, журнал происхождения
    excel/              чтение .xlsx по подписям, а не по адресам ячеек
    render/             оформление, диаграммы, слайды
templates/              шаблоны страниц, включая страницы ошибок
static/                 стили, сценарии, фирменный знак
deploy/                 средства развёртывания
docs/                   документация
tests/                  автоматические проверки
```

Пакет `rvp_report` перенесён из настольной версии без изменений,
за исключением удалённого интерфейса Tkinter. Порядок поиска данных
в рапорте без привязки к номерам строк и столбцов описан
в [docs/layout-editor.md](docs/layout-editor.md).

## Разграничение доступа

| Роль | Предоставляемые права |
|---|---|
| Администратор | полный доступ, включая справочники, учётные записи и повторный разбор архива |
| Руководство | дашборд, карточки отчётных суток, сводки, выгрузка презентаций |
| Работник промысла | загрузка и перезагрузка рапортов, работа с разметкой, а также права роли «Руководство» |

Каждому работнику создаётся персональная учётная запись.
Самостоятельная регистрация не предусмотрена: учётные записи создаёт
администратор системы. Выданный пароль подлежит замене при первом
входе.

## Обращение с данными

Файлы суточных рапортов и сформированные презентации содержат
сведения, составляющие коммерческую тайну, и в репозитории
не хранятся — соответствующие маски включены в `.gitignore`.

Персональные данные в базу данных не помещаются. Требование
распространяется не только на графу здравпункта: в рапорте
за 23.08.2026 фамилия и сведения о состоянии здоровья обнаружены
также в описании происшествия. В связи с этим сохраняются только
количество обращений и обезличенные признаки происшествия —
дочернее общество, месторождение, область события, тип. Свободный
текст остаётся в исходном файле, презентация формируется
непосредственно из него, минуя базу данных.
