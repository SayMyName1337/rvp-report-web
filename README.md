# Суточный рапорт — веб-приложение

Система хранения и анализа суточных рапортов ЦИТУ ООО «СК Русвьетпетро».
Заменяет настольную программу подготовки доклада: рапорт загружается
в браузере, данные накапливаются в базе, доступны сводки за период,
дашборд руководства и выгрузка презентации PowerPoint.

Проект системы — [docs/web-architecture.md](docs/web-architecture.md).

## Состояние

Пройдены первый и второй этапы: каркас приложения, пользователи
с ролями, вход, справочники и модель суточных данных. Следующий этап —
загрузка рапорта: очередь, разбор, запись в базу, идемпотентность
по дате.

Движок разбора проверен на 31 рапорте за август и 5 за июль:
разметка находится по подписям, обращений к эталонным адресам нет.

## Запуск для разработки

Требуется Python 3.12 и Docker.

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements/dev.txt
copy .env.example .env
```

В `.env` заменить `DJANGO_SECRET_KEY` на случайную строку.

База данных поднимается контейнером на порту **5442** — стандартный 5432
и соседний 5433 могут быть заняты уже установленным на машине PostgreSQL:

```bash
docker compose -f deploy/compose.dev.yaml up -d
```

Миграции, роли, администратор и запуск:

```bash
python manage.py migrate
python manage.py setup_roles
python manage.py createsuperuser
python manage.py runserver
```

Фоновые задачи выполняет отдельный процесс:

```bash
python manage.py qcluster
```

## Проверки

```bash
python -m pycodestyle apps config manage.py
python -m pytest
```

Ограничение длины строки — 88 знаков, задано в `setup.cfg`. Русские
подписи в схеме рапорта заметно длиннее английских идентификаторов,
и лимит в 79 знаков приводил бы к переносам в ущерб читаемости.

## Структура

```
config/                 настройки, адреса, точки входа
    settings/           base, dev, prod — по средам
apps/
    accounts/           пользователи и роли
    catalog/            справочники: месторождения, скважины, объекты
    reports/            суточные рапорты: загрузка, разбор, хранение
    analytics/          сводки за период и дашборд
    decks/              сборка презентации PowerPoint
rvp_report/             движок из настольной версии
    domain/             модель рапорта, проверки, журнал происхождения
    excel/              чтение .xlsx по подписям, а не по адресам ячеек
    render/             оформление, диаграммы, слайды
templates/              шаблоны страниц
static/                 стили, скрипты, фирменный знак
deploy/                 файлы развёртывания
docs/                   проектная документация
```

Движок `rvp_report` перенесён из настольной версии без изменений,
кроме удалённого окна Tkinter. Как он находит данные в рапорте,
не привязываясь к номерам строк и столбцов, описано в README
настольного проекта.

## Роли

| Роль | Что может |
|---|---|
| Администратор | всё, включая справочники, пользователей и повторный разбор архива |
| Руководство | дашборд, карточки суток, сводки, скачивание презентаций |
| Работник промысла | загрузка и перезагрузка рапортов, плюс всё, что доступно руководству |

У каждого работника личная учётная запись. Регистрации нет: записи
заводит администратор через панель управления, выданный пароль
пользователь меняет при первом входе.

## Данные

Суточные рапорты и собранные презентации содержат коммерческую тайну
и **не хранятся в репозитории** — они перечислены в `.gitignore`.
Сведения об обращениях в здравпункт относятся к специальной категории
персональных данных по 152-ФЗ: в базу записывается только их количество,
текст не сохраняется никогда.
